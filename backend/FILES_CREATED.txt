5. api/schemas.py (605 lines)
   Purpose: Pydantic validation models with JSON schema
   Data Models (13 total):

   a) DetectionResponse
      - Single object detection from frame
      - Fields: id, session_id, frame_number, timestamp, class_name, confidence
      - Fields: bbox, center, area, track_id
      - Validation: confidence 0-1, 4-element bbox, proper center coordinates
      - JSON schema example included

   b) IncidentResponse
      - Traffic incident detection
      - Fields: id, session_id, incident_type, severity, description, detected_at
      - Fields: confidence, related_detections, location, metadata
      - Status: accident, congestion, illegal_parking, speeding, etc.
      - Severity: low, medium, high, critical

   c) SessionResponse
      - Monitoring session information
      - Fields: id, name, type, status, created_at, updated_at, source
      - Fields: frame_count, duration_seconds, vehicle_count
      - Status: processing, completed, failed, stopped

   d) VehicleCountResponse
      - Aggregated vehicle statistics
      - Fields: total_vehicles, unique_vehicles, by_class, by_time_window
      - Fields: peak_time, peak_count
      - Time-windowed aggregation support

   e) TrafficFlowResponse
      - Traffic flow metrics
      - Fields: average_speed, congestion_level, flow_rate, density

   f) ChatRequest
      - User message to AI agent
      - Fields: session_id, message, include_context
      - Validation: session_id required, 1-2000 char message

   g) ChatResponse
      - Agent response with sources
      - Fields: session_id, message, sources, confidence
      - Confidence 0-1 scale

   h) ReportRequest
      - Report generation request
      - Types: summary, detailed, executive
      - Options: include_detections, include_incidents, include_charts

   i) ReportResponse
      - Generated report metadata
      - Fields: id, session_id, report_type, title, summary, generated_at
      - Download URL provided

   j) UploadResponse
      - File upload status
      - Fields: session_id, filename, file_size, status, message

   k) StreamStartRequest
      - Stream configuration
      - Fields: name, stream_url, fps
      - Validation: URL format (RTSP/HTTP) or 'webcam'
      - FPS: 1-120

   l) SessionStatsResponse
      - Session metrics
      - Fields: total_frames, processing_fps, detections_count, incidents_count
      - Fields: avg_detection_confidence

   m) HealthResponse
      - Component health status
      - Fields: status, timestamp, components, version
      - Status: healthy, degraded, unhealthy

   Special Models:

   n) PaginatedResponse[T] (Generic)
      - Generic pagination wrapper
      - Fields: items, total, page, page_size, total_pages
      - Properties: has_next, has_previous

   Enums:
   - DetectionClass: 15 vehicle classes (person, car, truck, bus, etc.)
   - IncidentType: 7 incident types (accident, congestion, speeding, etc.)
   - IncidentSeverity: 4 levels (low, medium, high, critical)

6. api/routes.py (844 lines)
   Purpose: REST API endpoints with error handling
   Total Endpoints: 12+ routes

   Session Management Endpoints:

   POST /api/sessions/upload
   - Upload video file and start processing
   - Accepts: MP4, AVI, MOV, MKV, FLV
   - Returns: UploadResponse with session_id
   - File size validation (max 5GB)
   - Background processing starts immediately
   - Error handling: 400 (invalid type), 413 (too large), 500 (error)

   POST /api/sessions/stream
   - Start RTSP stream or webcam processing
   - Params: name, stream_url, fps
   - Returns: SessionResponse
   - Concurrent session limit enforcement
   - Error handling: 400 (invalid URL), 429 (too many), 500 (error)

   GET /api/sessions/{id}
   - Get session information and status
   - Returns: SessionResponse
   - Error handling: 404 (not found)

   DELETE /api/sessions/{id}
   - Stop session and cleanup resources
   - Returns: status message
   - Cleanup happens in background
   - Error handling: 404 (not found)

   Detection & Analytics Endpoints:

   GET /api/sessions/{id}/detections
   - Get detections with pagination and filtering
   - Query params: page, page_size (1-500), class_name, min_confidence, frame_min, frame_max
   - Returns: PaginatedResponse[DetectionResponse]
   - Sortable, filterable by confidence and class
   - Error handling: 404 (not found)

   GET /api/sessions/{id}/incidents
   - Get detected incidents with pagination
   - Query params: page, page_size (1-100), severity, incident_type
   - Returns: PaginatedResponse[IncidentResponse]
   - Error handling: 404 (not found)

   GET /api/sessions/{id}/stats
   - Get aggregated session statistics
   - Returns: SessionStatsResponse
   - Metrics: total frames, processing FPS, detection count, incident count
   - Error handling: 404 (not found)

   GET /api/sessions/{id}/vehicle-counts
   - Get vehicle count aggregation
   - Returns: VehicleCountResponse
   - Breakdown by vehicle class and time window
   - Peak detection tracking
   - Error handling: 404 (not found)

   Chat & AI Agent Endpoints:

   POST /api/chat
   - Send message to LangGraph agent
   - Body: ChatRequest (session_id, message, include_context)
   - Returns: ChatResponse with agent answer
   - Context-aware responses using session data
   - Source attribution included
   - Error handling: 404 (not found), 500 (agent error)

   Report Generation Endpoints:

   POST /api/reports/generate
   - Generate analysis report
   - Types: summary, detailed, executive
   - Returns: ReportResponse with report_id
   - Background processing (returns immediately)
   - Options: include detections, incidents, charts
   - Error handling: 404 (not found)

   GET /api/reports/{id}/download
   - Download generated PDF report
   - Returns: PDF file stream
   - Checks completion status first
   - Error handling: 404 (report not found or not ready)

   System Endpoints:

   GET /api/health
   - Health check for all components
   - Returns: HealthResponse
   - Checks: database, redis, models
   - Status: healthy, degraded, unhealthy

   DELETE /api/sessions/{id}
   - Stop and cleanup session
   - Background task execution

================================================================================
USAGE EXAMPLES
================================================================================

1. Run the server:
   $ python main.py
   Server runs on http://localhost:8000

2. Access API documentation:
   - Swagger UI: http://localhost:8000/api/docs
   - ReDoc: http://localhost:8000/api/redoc

3. Upload a video:
   $ curl -X POST "http://localhost:8000/api/sessions/upload" \
     -F "file=@traffic.mp4" \
     -F "name=Highway A1"

4. Get detections:
   $ curl "http://localhost:8000/api/sessions/sess_123/detections?page=1"

5. Chat with agent:
   $ curl -X POST "http://localhost:8000/api/chat" \
     -H "Content-Type: application/json" \
     -d '{"session_id":"sess_123","message":"What traffic?"}'

6. WebSocket connection:
   const ws = new WebSocket('ws://localhost:8000/ws/sess_123');
   ws.onmessage = (e) => console.log(JSON.parse(e.data));

See QUICKSTART.md for more detailed examples.
